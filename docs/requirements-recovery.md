## セクション1: UI/UX要件（画面・レイアウト・アニメーション）

### REQ-101: 暖簾（のれん）くぐり演出による入室ゲート
**タグ**: AI暗黙判断
**現状の実装**: 初期表示で全画面を覆う暖簾（`Noren.tsx`）を表示。「のれんをくぐる」ボタンまたは画面クリックで暖簾が開くアニメーション（skew + scale + opacity、約1.2秒）が走り、その後チャット画面が現れる。左右パネルに「茶室」「案内」の縦書き文字。
**根拠・経緯**: 「茶室に入る」という世界観演出。会話ログ上に明示指示の記録がなく、AIが世界観構築のため自律追加したと推測。
**懸念・補足**: リピート訪問者にも毎回表示される。スキップ手段なし。クライアントが世界観として承認するか要確認（→ ヒヤリング Q1）。

### REQ-102: 茶室テーマのビジュアル世界観（配色・フォント）
**タグ**: AI暗黙判断
**現状の実装**: `bg-tea-bg` / `tea-dark` / `tea-mid` / `tea-green` 等の茶系カスタムカラー、`font-serif`（明朝系）を多用。和の茶室を想起させるトーン。
**根拠・経緯**: tayumano（お茶ブランド）の世界観に沿ったデザイン判断。AIが自律的にトーンを決定。
**懸念・補足**: 最終的なブランドカラー・フォントは DLS のデザイン納品で確定する想定。現状はAI仮デザイン（→ ヒヤリング Q2）。

### REQ-103: 背景のSVGファイル参照アーキテクチャ
**タグ**: 明示指示
**現状の実装**: `SvgBackground.tsx` が `/public/assets/background.svg` を `<img>` で参照。ファイルを差し替えるだけで背景変更が可能。`Background` ラッパー経由で z-0 に配置。
**根拠・経緯**: PM明示指示「背景もSVGファイル参照にしたい」。
**懸念・補足**: `PROGRESS.md` のSVG差し替え表が「現状はCSSグリッド」と古い記述のまま（実装は既にSVG化済み）。ドキュメント更新が必要。

### REQ-104: キャラクター/シーンオブジェクトのSVGファイル参照アーキテクチャ
**タグ**: 明示指示
**現状の実装**: キャラクターは `CharacterView.tsx` が `/public/assets/character.svg` を参照。急須は `SceneObjects.tsx` が `/public/assets/objects/teapot.svg` を参照。SVGアップロードのみで差し替え可能。
**根拠・経緯**: PM明示指示「外注先にSVGのアップロードのみで差し替えできる構造にしたい」。
**懸念・補足**: 新規オブジェクト**追加**は `SCENE_OBJECTS` 配列へのコード変更が必要（差し替えはノーコードだが追加はコード変更）。この区別をクライアントに伝える必要あり（→ ヒヤリング Q3）。

### REQ-105: クリックインタラクション（pop/wiggle アニメーション）
**タグ**: 明示指示
**現状の実装**: キャラクタークリックで `pop-once`（約550ms）、急須クリックで `wiggle-once`（約500ms）アニメーション。連打ガードあり。

## セクション4: データ要件（DB構造・Seedデータ・Shopify連携）

### REQ-401: DBアクセス抽象レイヤー（ChatDataStore IF）
**タグ**: 明示指示（DBアクセスモック要望に対応）
**現状の実装**: `ChatDataStore` インターフェースで topics / sales_rules / products / conversation_logs を抽象化。実装は `InMemoryDataStore`（Seed付き）。D1差し替え前提の疎結合設計。
**根拠・経緯**: PM明示指示「LLMモックとは別でDBアクセスモックも必要」。Cloudflare D1 移行を見据えた設計。
**懸念・補足**: InMemory はサーバーレス cold start でリセット。加えて Next.js dev 環境では API ルートごとにモジュールスコープが分離されることがあり、管理画面（`/api/sales-rules`）で追加したデータがチャット（`/api/chat`）に反映されない場合がある。管理画面 CRUD は「D1 接続後の UI 確認用プロトタイプ」であり、現状 Seed データはコード直接編集＋サーバー再起動での反映が正規手順。本番DB（D1）確定は寺園さんとの未決事項（§13）。

### REQ-402: 話題DB（Topics）とSeedデータ
**タグ**: AI暗黙判断（Seed内容）
**現状の実装**: Seed 2件「梅雨の過ごし方」「暑気払いの水出し緑茶」。enabled な話題が雑談コンテキストとしてプロンプトに注入される。
**根拠・経緯**: 機能デモ用のサンプルデータをAIが考案。季節性（梅雨・夏）を持たせている。
**懸念・補足**: **季節性のあるSeedは時期が過ぎると陳腐化する**（梅雨は今、夏季限定は夏のみ妥当）。運用で誰がいつ更新するか未定（→ ヒヤリング Q16）。

### REQ-403: 営業ルールDB（SalesRules）とSeedデータ
**タグ**: AI暗黙判断（Seed内容）/ 明示指示（仕組み）
