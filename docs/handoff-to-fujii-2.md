## 1. 現在の実装状況

### 1-A. レコメンドのアーキテクチャ（前回から変更あり）

前回（2026-06-22）の申し送りでは「ハードガードレールはLLMに守らせる」と説明しました。  
その後の実装で、**ガードレール適用と商品選択をサーバー側のコードで完全に確定させる設計に変更しました**。

```
【変更前】
ユーザー発言 → Gemini（プロンプト内のルールを自分で適用して商品を選ぶ）→ 返答

【変更後】
ユーザー発言
  ↓
サーバー側の recommend() 関数が商品を確定（LLM不使用・決定的）
  ↓
Gemini へ「この商品を紹介して」と指示 → 口調・文章だけをLLMが担当
```

**メリット**: LLMが確率的にガードレールを破る事故がなくなる。テストが書けるようになった（現在12件のユニットテスト通過）。  
**影響**: プロンプト内の「レコメンド制御（ハード→ソフトの順で…）」セクションは、引き続きLLMへの参考指示として残しますが、**実際の商品選択はコードが行います**。

## 2. 確認・承認をお願いしたい事項

### ❶ 【最優先・変更禁止ブロックの旧商品名】要承認

**問題**: `character.ts` の「変更禁止（コンプラ審査済み）」ブロックに、以下の記述があります。

```
tayumanoの商品（Midnight Roaster / Silent Awakening）を会話の流れに合わせて自然に紹介する。
```

`Midnight Roaster`（深呼吸のほうじ茶の英語サブタイトル）と `Silent Awakening`（静かなる覚醒の煎茶）は旧商品名で、現在の商品カタログ（こがれ・とこのは・あまもあ・ながとき・茶のことはじめ）には存在しません。  
**このままだとGeminiが実在しない商品名を口にする可能性があります。**

このブロックは藤井さんの承認なしに変更できない設計になっているため、確認をお願いします。

**選択肢**:
- A. 現商品名（こがれ・とこのは 等）に差し替えてよい ← 推奨
- B. 英語サブタイトル表記は廃止し、商品名（日本語）のみで統一してよい
- C. このブロック全体の書き直しを依頼する（商品説明は動的カタログで賄うので不要）

**注**: SOURCE_TEXT（知識ベース）の `【武器A: 深呼吸のほうじ茶 (Midnight Roaster)】` の記述も同様に古いままです。あわせて確認をお願いします。

### ❷ 【安全上の問題】カフェインゼロ要求時の挙動

**問題**: 現在の5商品にカフェイン「ゼロ」の商品がありません。  
「カフェインゼロのお茶が欲しい」と言われたとき、コードのフォールバック処理が全商品を対象に戻してしまい、**中カフェインの「茶のことはじめ」を"カフェインを控えたいときは"と推薦する**ケースが発生します。

これは妊娠中・授乳中・子ども向けに「ゼロ」を求めたケースで特に問題です。

**選択肢**:
- A. カフェインゼロ商品を1品追加する ← 根本解決
- B. 「現在はゼロカフェイン商品がございません。お探しでしたらXXをご検討ください」と正直に返す ← コード修正で対応可能・今すぐできる
- C. 現状維持（ゼロ要求は想定ユーザー層に少ない）

**こちらとしてはBを今すぐ適用し、Aは実商品データをいただいた後に検討する流れが現実的と考えています。**

### ❹ 【挙動の確認】「ゆっくりしたい」→ 茶のことはじめが返る

**現象**: 「ゆっくりしたい」「癒されたい」「ほっこりしたい」など、曖昧なリラックス系の言葉では、5商品すべてが「落ち着き」ムードを持っているため得点差がつかず、初心者セットの「茶のことはじめ」が返ります。

これは「迷ったらまずセットを」という安全側の判断ですが、意図通りでしょうか。

**選択肢**:
- A. 問題ない（セットが出るのは合理的）
- B. この場合は商品を出さず「どんなシーンで飲みたいか」を引き出す会話を優先してほしい
- C. 各商品の「落ち着き」ムードを絞り込み、区別できるようにする（例:「こがれ」は「夜の落ち着き」「あまもあ」は「甘い癒し」に特化）

## 3. 現在の設計のご説明（技術的背景）

### 3-A. モック/本番の4象限

開発・テスト・本番のモードを整理すると以下の4象限になります。

| | テスト用固定返答（モックロジック） | 実Gemini（本番ロジック） |
|---|---|---|
| **仮の商品データ（現在）** | A: 社内テスト用（`MOCK_CHAT=true`） | **B: 現在の本番デフォルト** |
| **実Shopifyデータ（将来）** | C: デバッグ用（未実装） | **D: 最終形態（目標）** |

現在は **B（仮データ × Gemini本番）** で動いています。藤井さんから実商品データをいただき次第、**D（実データ × Gemini本番）** に移行します。移行に必要な変更は `db/index.ts` の商品データ差し替えのみです（他のロジックは無改修）。

### 3-B. 5商品の全パターン早見表

現在の仮データ・仮ロジックで、どのユーザー発言がどの商品に対応するかの全体像です。  
**属性値は仮のため、実データ提供後に変わります。**

| ユーザーの発言パターン | 返す商品 | 理由 |
|----------------------|---------|------|
| 「夜」「カフェイン控えたい」「睡眠」「妊娠中」「子どもに」 | **こがれ** | カフェイン低・唯一の候補 |
| 「朝シャキッと」「集中したい」「仕事に」「覚醒」 | **とこのは** | シーン×気分スコア最高 |
| 「来客に」「お客様に出す」「特別な」「ご褒美」 | **ながとき** | 来客シーン・特別な時間ムード |
| 「甘い」「渋みが苦手」「苦くない」「さっぱり」（辞書形） | **あまもあ** | キャンペーン上書き |
| 「甘くて」「渋みのない」「甘さがほしい」（活用形） | **あまもあ** | 属性スコア：甘味強+渋弱 |
| 「初心者」「はじめて」「迷ってる」「プレゼントに」「ギフト」 | **茶のことはじめ** | 初心者セット導線 |
| 「ゆっくりしたい」「癒されたい」「ほっこり」（曖昧） | **茶のことはじめ** | 全商品同点→セット常勝（❹参照） |
| **「カフェインゼロ」「デカフェ」** | ⚠️**茶のことはじめ（中カフェイン）** | バグ（❷参照） |
| 「こんにちは」「最近どう?」「梅雨だね」（純粋雑談） | なし（雑談継続） | 商品を押しつけない |

### 3-C. recommend() 関数の優先順位（実装済み）

```
0️⃣ キャンペーン上書き（営業ルールのキーワード一致）
  ↓ なし
① カフェイン除外（安全最優先・コードで機械的に適用）
  ↓
② 苦手除外（渋み・苦み否定語を検出）
  ↓
③ 好み・シーン・気分スコアリング
  ↓
④ 初心者セット（スコアゼロかつ初心者意図あり）
  ↓
☕ カフェイン制約のみ（スコアゼロでも安全制約内で1点）
  ↓
null（純粋雑談 → 商品を出さない）
```
